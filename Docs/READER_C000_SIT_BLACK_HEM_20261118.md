# 读卡器 C000 坐姿黑面：旗袍下摆前片（2026-11-18）

F 组 f-yvonne。e-fork-2 在读卡器测新版面时撞到，回报为「坐姿时头发上有黑色破面」。查下来**不是头发**，是旗袍下摆前片。
还没修：源头是动态骨碰撞（下摆被大腿顶成直板、穿进腿），和 Yvonne 服装二大腿破图同一类，整合后一起改。

## 重现
- 卡 C000（fin 爱莉希雅1.1）服装 1，「Demo：坐姿 01」。F 树一般读卡器（没加 `-OKDreamReader`）、GPU 与 CPU 蒙皮都有。
- 6 张卡 × 服装 1–2（C000 C001 C002 C041 C044 C048）只有 C000 服装 1 有。
- **间歇性**：同一个姿势隔几秒会出现、消失。正面约每 5 张 1 张，她的左侧（yaw -90）约一半，右侧（yaw 90）很少。
  所以验「修好没」要用连拍 ≥40 张（正面＋yaw -90）、0 张黑才算，不能看一两张。

## 逐项排除（每组连拍，「黑」= 画面下半中段黑占比 > 0.05）
| 对照 | 结果 | 说明 |
|---|---|---|
| `ok.Debug.Outline 0`（关全部外框壳） | 0/10 | 黑的是外框壳 |
| 藏 `cf_o_bot_china_d`（下摆本体） | 0/40 | 是本体自己的壳 |
| 藏 `_ura`／`_kazari`，本体留着 | 仍黑（3/10、2/20、2/20） | 不是内侧网格、装饰的壳；也不是两片壳互穿 |
| 站姿正面、低角度正面、低角度从背后（看得到前后片内侧） | 0/6，两张都不黑 | 不是全域绕序／负缩放×面向号码（那样站姿也会黑） |
| CPU 蒙皮（`-CpuSkin`） | 正面 9/40、yaw -90 20/30 | 不是 GPU 变形路径的 bug |
| `ok.ClothCover 0`、`ok.ClothGpu 0` | 20/30、12/30 | 不是布料推开 |
| 黑帧与不黑帧的蒙皮法线（`ok.Debug.DumpPartDrawn`，CPU 蒙皮） | 法线与面向相反的三角形：黑帧 56–68、不黑帧 81（共 1470），位置分散 | 不是「翻起时法线反向、壳被推到相机侧」 |

下摆三块（本体、`_ura`、`_kazari`）都是 `M_ForgeOpaque`（双面）＋`M_ForgeOpaque_Outline`；来源有外框（`_linewidthG=0.47379`），
所以「跟来源关掉外框」不成立。

## 结论
关外框、只留前片本体时（`bare` 组），前片格纹和大腿叠在一起像半透明；材质的 OpacityMask 是常数、没开 dither，
所以是两个面几乎重合在抢深度：**前片贴着或穿进腿的表面**。本体被腿挡住，它的外框壳（外扩约 0.47 线宽）露在腿外，
从前片内侧那面看过去就是整片外框色。
因果：同卡同衣同外框设定，站姿（下摆自然垂下）不黑、坐姿（下摆被顶起穿腿）才黑。外框与法线都没坏。

修的方向是动态骨碰撞（大腿碰撞体／半径），不是调外框宽度（全域调小会让所有角色轮廓变细）。
和 Yvonne 服装二大腿一起改时，两个症状各自要有一组前后对照。原作同姿势没有对照（手上没有原作 dump）：原作可能也有，未对照。

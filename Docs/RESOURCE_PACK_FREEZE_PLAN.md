# 資源包格式凍結：讓這次重載是最後一次（方案，2026-11-24）

**範圍**：`Content/IndependentResources/base_v1` 這個資源包的格式紀律，以及程式包更新後「就地修」而不是「叫玩家重下 34.7 GB」的機制。不含版本閘本身（已完成，[相容性閘方案](RESOURCE_PROGRAM_COMPAT_GATE_PLAN.md)，Rust 那頭是 `Tools/ok-extract/src/resources.rs`，`9248518e4`）。

**使用者定的目標（2026-11-24）**：這次（資源版本 3）**可以**讓玩家重載一次完整包，但**希望是最後一次**。所以這份不是在規劃補丁包，而是在規劃「以後程式改動不再需要新資源包」的紀律與機制。重載是一次性的額度，用掉就沒了。

## 0. 為什麼光有閘不夠

11-24 炸掉的是 `mods_index.db`（schema 1 的庫被需要 schema 2 的程式疊上去）。閘現在擋得住了，但擋下來之後唯一的答案是重下完整包——而那個檔案**本來就能在玩家機器上重建**，它的來源是玩家自己的 `mods/` 目錄，不是打包者的。換句話說：那次事故不是資源包真的過期，是我們把一個衍生物當成了資源包的版本面。

所以紀律的第一條是分類。

## 1. 資源包裡的三類東西

| 類 | 有哪些 | 玩家能不能重建 | 格式改了怎麼辦 |
|---|---|---|---|
| **一、原始轉出物**（不可重建） | `models/`（`.okmodel`）、`sources.okidx`、`anims/`、`h/`、`paired/`、`studio/`（`.ogg`） | **不行**。沒有原作遊戲的玩家根本沒有來源 | 從 v3 起**凍結**：只准往後加，舊檔必須照樣讀得開。要真的破壞，得再發一次資源包＝用掉那次額度 |
| **二、衍生物**（可重建） | `mods_index.db`、`shared_mods.txt`、`shader_states.json`、`studio_items.json`、`studio_anims.json`、`studio_voices.json`、`studio_child_animations.json`、`converted.tsv`、`models/.gitignore` | **能**，從第一類＋玩家自己的遊戲／`mods/` 重建 | **不該算資源包的版本面**。格式改了就在本機重建，程式自己做掉 |
| **三、本機狀態**（不屬於包） | `edits.stamp`、`missing.txt`、`work/`、`*.okpreview` | — | 打包時不帶（打包自檢要驗這一條） |

`mods_index.db` 放在第二類還有第二個理由：包裡那一份記的是**打包者的** `mods` 目錄（`meta.mods_dir`），對玩家本來就是別人的視野（閘的 `mods_index_foreign` 警告就是在講這件事）。玩家真正該用的那一份，只能在他自己機器上生。

## 2. 「最後一次」怎麼落地

### 2.1 第一類：凍結，而且凍結要是程式會檢查的

文件上的君子協定會忘。所以：

1. **釘住的 v3 樣本進版控**：每種第一類檔案取一個小樣本（幾 KB，`Tools/ok-extract/tests/fixtures/v3/`），測試用它開、比對已知答案。這些樣本必須是**自製內容或原作無關的最小構造**，不能是原作衍生資料（版控規則）；做不出無版權樣本的那幾種，改為在測試裡**用程式自己生一份 v3 格式**再讀，並把生成端的常數釘死。
2. **讀取端的明文測試**：未知欄位忽略、缺欄位走預設，各一條測試。
3. **只准 append**：新資料一律新檔或新 token，不改既有記錄的意義。要換編碼（例如模型壓縮換掉），走「**讀舊寫新**」——新編碼只用在新轉出的東西，舊的照樣讀——而不是要求全體重轉。
4. **`RESOURCES_MIN` 從 3 起不准再往上抬**。要抬的人在這份文件裡留下日期、理由，以及使用者同意再發一次資源包的紀錄。這條就是「最後一次」的實際形式；沒有這條，其餘都只是建議。

### 2.2 第二類：程式自己就地重建，不擋人

閘現在把 `mods_index_schema` 當 `block`。要改成「可本機修」的一級：

- `problems[]` 那筆帶 `fixable_locally: true` 與 `command`（這兩個欄位閘已經留好了，就是為這件事）。
- **程式啟動時自己做掉**：知道遊戲路徑就重建，不要讓玩家去打指令。重建是長動作 → 照專案規則上 `OKBusy` 進度條，不自己做文字提示。
- 不知道遊戲路徑（玩家只有包、只開 OK 卡）→ **不該擋**。OK 卡不經過 mod 索引。只有在真的要開原作卡時才講「要指遊戲目錄才能算 mod」。
- 重建結果**不寫回資源包**：包可能是唯讀的，也可能是硬連結和別的安裝共用。寫到 `Saved/LibraryLocal/<庫指紋>/mods_index.db`，程式讀的時候本機那份優先。庫指紋用 `oklib.json` 加庫路徑，不要用內容雜湊（開庫時算不起）。
- 一樣的處理給 `shader_states.json`、`studio_*.json`：缺或版本不符就本機重建到同一個資料夾。

這一改之後，11-24 那一類事故的正確結局是：**玩家開程式，進度條跑三十秒，照常玩**。

### 2.3 這次重載要一次補到位

既然要重載一次，第一類該預留的要趁這次做完，不要留到下次：

- 每種第一類檔案的標頭都要有自己的格式整數（目前 `sources.okidx` 沒有版本欄位，閘只能用 selftest 兜底）——**這次加上**，以後才有得比、也才有得遷移。
- 預留擴充位：記錄尾端留 TLV 或 `extra` 欄位，讓「加一個欄位」不必動格式整數。
- 盤一次「程式裡還有哪些常數會影響第一類的解讀」，連同 `resources-stamp` 一起印出來，別留第二個會忘記的地方。

這三件是這份方案裡唯一**必須在這次重載前完成**的工作，其他都可以之後再做。

## 4. 驗收

1. 把一份 v3 包的 `mods_index.db` 換成 schema 1，**指著遊戲目錄**啟動：進度條跑完，原作卡照常開，缺件清單正確（不是 42 件那種假清單），資源包本身沒有被改寫。
2. 同上但**不指遊戲目錄**：OK 卡照常開，畫面上沒有任何擋人訊息；按下開原作卡才講「要指遊戲目錄」。
3. 把包設成唯讀（或整個庫用硬連結共用給兩個安裝），重跑 1：兩邊各自在自己的 `Saved/LibraryLocal/` 生，互不干擾。
4. 刪掉 `shader_states.json` 與 `studio_items.json`：本機重建，不要求重下包。
5. 拿 v3 的釘住樣本，用加了欄位的新程式讀：讀得開，未知欄位被忽略，測試綠。
6. 把第一類某個檔的格式整數抬一號（人工改樣本），新程式讀：報「資源包太舊」並指名是哪一種檔，不是籠統一句。
7. 打包自檢：故意把 `edits.stamp` 與一個 `*.okpreview` 留在資源那一側，打包要失敗。

## 5. 風險

- **「只准 append」會擋住真正的優化**。例如模型編碼換掉能省幾 GB。對策是 §2.1 第 3 點的讀舊寫新；真的要全體重轉，就是用掉那次額度，要使用者同意。
- **本機重建的時間**。`mods_index` 一次走完整個 `mods/` 樹（~7300 個 manifest，冷的大約數秒到數十秒）。只在 schema 不符時做一次，之後讀 `Saved/LibraryLocal/`；但要確認不會每次啟動都做（判斷用 `meta.schema` 加 `meta.mods_dir`，不要用 mtime）。
- **`Saved/` 是可丟的**（專案既有紀律）。本機重建的產物放 `Saved/` 符合這條——丟了就再生一次，不是資料遺失。但要確認玩家包的 `Saved/` 不會被安裝流程清掉，否則每次更新程式都要重建一次（可以接受，只是要知道）。
- **共用程式碼**：`Tools/ok-extract` 是 C／E／F 三組共用，改完要 `cargo check --release` 與 `--no-default-features`，並實際連結 `OpenKoikatsu` Win64 Development 與 `OpenKoikatsuEditor`。
